<a id="bug-01"></a>
## BUG-01. Вход по резервному коду 2FA невозможен

| | |
|---|---|
| **Компонент** | `POST /api/login`, `app/routers/auth.py` |
| **Серьёзность / приоритет** | Critical / High |
| **Воспроизводимость** | 100% |

**Предусловия:** пользователь `alice` / `secret123` включил 2FA (`/2fa/setup` → `/2fa/verify`) и сохранил резервные коды из ответа `/2fa/setup`.

**Шаги воспроизведения:**
1. `POST /api/login`
   ```json
   {"username": "alice", "password": "secret123", "twoFactorCode": "<один из backupCodes>"}
   ```

**Фактический результат:** `401 {"detail": "Неверный код 2FA"}`.

**Ожидаемый результат:** `200` с токеном. Использованный резервный код удаляется и повторно не принимается.

**Влияние:** пользователь, потерявший телефон с аутентификатором, не сможет войти в аккаунт, хотя система выдала ему резервные коды. Кроме того, коды хранятся в БД (`users.backup_codes`) в открытом виде.

**Причина:** `login()` проверяет `twoFactorCode` только через `totp_verify()`, а поле `backup_codes` нигде не читается.

**Автотест:** `test_known_bugs.py::test_login_with_backup_code`

<a id="bug-02"></a>
## BUG-02. Повторный `/2fa/setup` молча перезаписывает секрет включённой 2FA

| | |
|---|---|
| **Компонент** | `POST /api/2fa/setup` |
| **Серьёзность / приоритет** | Major / High |
| **Воспроизводимость** | 100% |

**Предусловия:** у пользователя включена 2FA (`two_factor_enabled = true`).

**Шаги воспроизведения:**
1. `POST /api/2fa/setup` с токеном пользователя.
2. Выйти и попытаться войти с кодом из приложения-аутентификатора.

**Фактический результат:**
- Шаг 1 возвращает `200` с новым `secret` и новыми `backupCodes`. Флаг `two_factor_enabled` остаётся `true`, но секрет уже заменён.
- Шаг 2 возвращает `401 "Неверный код 2FA"`: старый аутентификатор больше не подходит.

**Ожидаемый результат:** `400`/`409` («2FA уже включена»). Перенастройка возможна только после отключения 2FA с подтверждением текущим кодом.

**Влияние:** пользователь может случайно заблокировать себе вход. Злоумышленник с украденным токеном может перепривязать 2FA на своё устройство без знания текущего кода.

**Автотест:** `test_known_bugs.py::test_setup_2fa_when_already_enabled_is_rejected`

## BUG-03. Удаление несуществующего актива возвращает 200

| | |
|---|---|
| **Компонент** | `DELETE /api/assets/{asset_id}` |
| **Серьёзность / приоритет** | Minor / Low |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. `DELETE /api/assets/999999` с валидным токеном.

**Фактический результат:** `200 {"message": "Актив удален"}`. Тот же ответ приходит при попытке удалить чужой актив, хотя он не удаляется.

**Ожидаемый результат:** `404 {"detail": "Актив не найден"}`, как в `PUT /assets/{id}/price`.

**Влияние:** клиент показывает пользователю ложное сообщение об успешном удалении. Ответы API для одинаковых ситуаций несогласованы.

**Автотест:** `test_known_bugs.py::test_delete_missing_asset_returns_404`

| | |
|---|---|

| **Серьёзность / приоритет** | Minor / Medium |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. `POST /api/register`
   ```json
   {"username": "alice", "email": "not-an-email", "password": "secret123"}
   ```

## BUG-05. Можно создать актив с отрицательным количеством и ценой

| | |
|---|---|
| **Компонент** | `POST /api/assets`, `PUT /api/assets/{id}/price`, `AssetCreate` / `PriceUpdate` |
| **Серьёзность / приоритет** | Major / Medium |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. `POST /api/assets`
   ```json
   {"portfolio_id": 1, "asset_type": "stock", "name": "Apple", "quantity": -5, "purchase_price": -100}

## BUG-06. Нечисловой `id` в `/assets/update-prices` вызывает 500

| | |
|---|---|
| **Компонент** | `POST /api/assets/update-prices`, `BulkPriceUpdate` (`prices: list[dict]`) |
| **Серьёзность / приоритет** | Major / Medium |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. `POST /api/assets/update-prices`
   ```json
   {"prices": [{"id": "abc", "price": 10}]}
   ```

**Фактический результат:** `500 Internal Server Error`. В логе сервера:
```
psycopg.errors.UndefinedFunction: оператор не существует: integer = character varying
```

**Ожидаемый результат:** `422` с описанием ошибки валидации.

**Причина:** элементы `prices` не типизированы (`list[dict]`), значения без проверки попадают в SQL-запрос.

**Влияние:** любой авторизованный пользователь может вызвать необработанную ошибку на сервере. Текст ошибки БД попадает в логи.

**Автотест:** `test_known_bugs.py::test_bulk_update_with_invalid_id_returns_422`

<a id="bug-07"></a>
## BUG-07. Приложение запускается с дефолтным `JWT_SECRET`

| | |
|---|---|
| **Компонент** | `app/config.py` |
| **Серьёзность / приоритет** | Critical / High |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. Запустить сервер без переменной `JWT_SECRET` и без `.env`.
2. Подписать токен `{"userId": 1}` ключом `your_secret_key_here`, который виден в открытом репозитории.
3. `GET /api/me` с этим токеном.

**Фактический результат:** сервер стартует без предупреждений. Поддельный токен принимается, и запрос выполняется от имени пользователя с `id=1`.

**Ожидаемый результат:** при отсутствующем или слишком коротком (< 32 байт) `JWT_SECRET` приложение не запускается и сообщает об ошибке конфигурации.

**Влияние:** полный обход аутентификации на любом стенде, где забыли задать секрет.

**Автотест:** `test_known_bugs.py::test_default_jwt_secret_is_rejected`

<a id="bug-08"></a>
## BUG-08. CORS разрешает любой Origin вместе с credentials

| | |
|---|---|
| **Компонент** | `app/main.py`, `CORSMiddleware` |
| **Серьёзность / приоритет** | Major / Medium |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. ```
   OPTIONS /api/me
   Origin: https://evil.example.com
   Access-Control-Request-Method: GET
   ```

**Фактический результат:** в ответе есть `Access-Control-Allow-Origin: https://evil.example.com` и `Access-Control-Allow-Credentials: true`.

**Ожидаемый результат:** разрешены только домены из настройки (например, `CORS_ORIGINS`). Для чужого Origin заголовок `Access-Control-Allow-Origin` не возвращается.

**Причина:** `allow_origins=["*"]` вместе с `allow_credentials=True`. В этом случае Starlette отражает любой Origin запроса.

**Автотест:** `test_known_bugs.py::test_cors_rejects_unknown_origin`

<a id="bug-09"></a>
## BUG-09. `total_value` портфеля всегда 0

| | |
|---|---|
| **Компонент** | `GET /api/portfolios`, поле `portfolios.total_value` |
| **Серьёзность / приоритет** | Major / Medium |
| **Воспроизводимость** | 100% |

**Шаги воспроизведения:**
1. Зарегистрироваться и получить id портфеля через `GET /api/portfolios`.
2. `POST /api/assets`: `quantity = 2`, `current_price = 150`.
3. `GET /api/portfolios`.

**Фактический результат:** `"total_value": 0.0`.

**Ожидаемый результат:** `"total_value": 300.0`, то есть сумма `quantity × current_price` по активам портфеля. Значение должно пересчитываться при добавлении, удалении активов и изменении цен.

**Причина:** колонка `total_value` заполняется только значением по умолчанию, код её нигде не обновляет.

**Автотест:** `test_known_bugs.py::test_portfolio_total_value_updates`
